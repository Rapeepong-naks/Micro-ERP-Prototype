# Khonnai — สเปกต้นแบบและแผนทดสอบ

อัปเดต 27 ตุลาคม 2026 เอกสารนี้เป็นแหล่งเดียวสำหรับคำศัพท์ กติกา flow ขอบเขต และโจทย์ทดสอบของเว็บต้นแบบ หากพฤติกรรมใน `prototype/` ต่างจากเอกสาร ให้แก้โค้ดและสเปกในงานเดียวกัน

## เป้าหมายและผู้ใช้

ระบบช่วยร้านส่งเสื้อผ้าและชุดชั้นในขนาดเล็ก โดยเริ่มจากร้านนำร่อง เจ้าของร้านทำงานบนมือถือและอาจไม่คุ้นกับเทคโนโลยี งานหลักคือดูสต็อก รับของเข้า จอง และออกบิล ผู้ช่วยร้านดูสต็อกและรับของเข้าได้ แต่สิทธิ์จริงต้องบังคับที่ backend ในระยะสร้างแอป

UI ใช้ภาษาไทยตรงไปตรงมา ตัวหนังสืออ่านง่าย ปุ่มใหญ่ แสดงยอดรวมเด่น และบอกผลก่อนการกระทำที่กระทบสต็อก แท็บ **บิล** เริ่มที่ออกบิล ประวัติเป็นทางเลือก หน้าตรวจยอดก่อนขายใช้หน้าตาแบบบิลกระดาษและระบุว่า *ยังไม่ใช่บิลเงินสด* ปุ่มพิมพ์/บันทึก PDF ใช้ให้ลูกค้าดูยอดได้ก่อนยืนยัน

## คำศัพท์และกติกาสินค้า

| คำ | ความหมาย |
| --- | --- |
| รุ่น | ชื่อหรือรหัสสินค้า ก่อนระบุไซซ์และสี |
| ตัวเลือกสินค้า | รุ่น + ไซซ์ + สี สำหรับแพ็กสีเดียว; รุ่น + ไซซ์ สำหรับแพ็กคละสี |
| ตัว | สินค้าหนึ่งชิ้น |
| แพ็ก | หน่วยขายและหน่วยสต็อก จำนวนตัวต่อแพ็กกำหนดตามรุ่น |
| โหล | จำนวนแพ็กของตัวเลือกเดียวกันที่รวมได้ 12 ตัว ใช้เมื่อ 12 หารจำนวนตัวต่อแพ็กลงตัว |
| ในร้าน | จำนวนแพ็กที่มีอยู่จริง รวมของที่จองแล้ว |
| จองไว้ | จำนวนแพ็กที่กันให้ลูกค้า แต่ยังไม่ขาย |
| ขายได้ | ในร้าน − จองไว้ |
| จุดเตือนใกล้หมด | เกณฑ์ต่อหนึ่งตัวเลือกสินค้า ไม่ใช่ยอดรับเข้า และไม่ถูกบวกกับสต็อก |
| ยี่ปั๊ว | ผู้ค้าส่งที่ร้านรับสินค้าเข้ามา |

สต็อกนับเป็น **แพ็กต่อหนึ่งตัวเลือกสินค้า** รุ่นแพ็กคละสีมีสต็อกหนึ่งค่าต่อไซซ์ รุ่นแพ็กสีเดียวมีหนึ่งค่าต่อคู่ไซซ์×สี ช่องสต็อกว่างคือยังไม่ได้นับ ต่างจากเลข 0 ที่นับแล้วไม่มีของ การแกะแพ็กขายเป็นตัวและการย้ายหน่วยสต็อกอยู่ระยะถัดไป

ราคาปัจจุบันเก็บต่อรุ่น บิลและการจองเก็บราคาของแต่ละบรรทัด ณ เวลาสร้าง จึงไม่เปลี่ยนตามราคาประจำรุ่นในภายหลัง เจ้าของร้านแก้ราคาเฉพาะบรรทัดร่างได้โดยไม่กระทบรุ่นเดิม ราคาแยกตามไซซ์หรือสีและบันทึกเหตุผลการลดราคายังต้องออกแบบ

## Flow ที่ต้องรักษา

| งาน | ก่อนยืนยัน | หลังยืนยัน |
| --- | --- | --- |
| ออกบิล | เริ่มที่ร่างบิล → เลือกรุ่น/ไซซ์/สี/จำนวน → ดูสรุปยอดและพิมพ์ได้; ยังไม่ตัดสต็อก | แสดงบิลเงินสดพร้อมเลขบิลและยอด; ตัดสต็อก; กลับไปเริ่มบิลใหม่ได้ |
| จอง | สร้างร่างและตรวจยอด; กันของจากจำนวนขายได้ | แสดงรายละเอียดการจอง; ของยังอยู่ในร้านแต่ขายให้คนอื่นไม่ได้ |
| ขายจากการจอง | เปิดการจอง → ดูสรุปยอดก่อนขาย → ยืนยันอีกครั้ง | ลดจำนวนจองและสต็อกจริง เปิดบิลที่ลิงก์กลับรายการจอง |
| รับของเข้า | ค้นหลายรุ่นในรอบเดียว กรอกจำนวนจริง | เพิ่มสต็อกและแสดงรายละเอียดรายการที่บันทึก |
| แก้รับของ/การจอง | เปิดข้อมูลเดิม แก้จำนวน | ปรับเฉพาะส่วนต่าง และไม่อนุญาตให้ของในร้านต่ำกว่าจำนวนจอง |
| ยกเลิก | แสดงผลต่อสต็อกก่อนยืนยัน; กดไม่ยกเลิกแล้วข้อมูลคงเดิม | แสดงสถานะยกเลิกและยอดที่คืนหรือหักจริง |

รูปแบบบิลเป็น **เอกสารแสดงรายการขาย** ต้นแบบยังไม่บันทึกการรับเงิน จึงห้ามสื่อว่า “ชำระแล้ว” สรุปยอดก่อนขายต้องติดป้ายชัดว่าไม่ใช่บิลจริงและไม่ตัดสต็อก การจองเกิดได้ไม่ว่าลูกค้าสั่งทาง LINE หรือช่องทางอื่น ระยะแรกยังไม่เชื่อม LINE OA หรือตรวจสลิปอัตโนมัติ

บิลและการจองเลือก **รับหน้าร้าน** (ค่าเริ่มต้น ค่าส่ง 0) หรือ **จัดส่ง** ถ้าจัดส่งต้องกรอกชื่อขนส่งตามที่ลูกค้าต้องการ เบอร์ผู้รับตัวเลข 9–15 หลัก ที่อยู่ และค่าส่งที่ร้านตกลงเอง 0–100,000 บาท ทศนิยมไม่เกินสองตำแหน่ง ชื่อผู้รับต่างจากชื่อลูกค้าใส่ได้ ยอดรวม = ราคาสินค้ารวม + ค่าส่ง ทั้งสรุปก่อนขาย บิลจริง บิลที่แก้ และบิลจากการจองแสดงข้อมูลชุดเดียวกัน ค่าส่งไม่กระทบจำนวนสต็อก ต้นแบบยังไม่คำนวณค่าส่งอัตโนมัติ ไม่สร้างเลขพัสดุ และยังไม่บันทึกสถานะการชำระเงิน ยอดในแคตตาล็อกลูกค้ายังไม่รวมค่าส่งเพราะวิธีรับสินค้าต้องให้ร้านยืนยันก่อน

## การออกแบบและขอบเขตต้นแบบ

- สี Soft Azure น้ำเงิน `#3878DB` และส้ม `#F99545`; ใช้เฉดที่เข้มพอสำหรับข้อความและปุ่ม ฟอนต์ Noto Sans Thai ฝังในเว็บ
- เดสก์ท็อปแสดงกรอบ 375 × 812 CSS px; มือถือใช้เต็มจอ ปุ่มสำคัญและแถบเมนูอยู่ด้านล่าง
- ค้นรุ่นด้วยชื่อ รหัส หมวด หมวดย่อย หรือไซซ์ หน้าขายแสดงสีเฉพาะไซซ์ที่เลือก และเก็บจำนวนจากไซซ์อื่นไว้ในตะกร้า
- หน้าสต็อกของร้านจัดกลุ่มตามไซซ์ แสดงยอดในร้าน/จองไว้/ขายได้ครบทุกสี รวมสีที่หมด; แคตตาล็อกลูกค้าแสดงเฉพาะไซซ์และสีที่ขายได้ รุ่นที่หมดทั้งรุ่นอยู่ในหัวข้อพับแยก เพื่อให้รายการหลักอ่านง่าย
- สีหรือไซซ์ที่ไม่มีขายอีกให้ใช้ “เลิกขายตัวเลือก” แทนการลบถาวร ทำได้เมื่อในร้านและจองไว้เป็น 0 แพ็ก และยังมีตัวเลือกอื่นที่ขายอยู่ในรุ่น บิล/ประวัติเดิมยังอ้างอิงได้และนำกลับมาขายได้
- รูปสินค้าอยู่เฉพาะ session เบราว์เซอร์ปัจจุบัน รูปที่เจ้าของร้านเลือกจะไม่ปรากฏบนอีกเครื่อง ข้อมูลหลังร้านหายเมื่อรีเฟรช รายการที่ลูกค้าสนใจเก็บใน `localStorage` เฉพาะเบราว์เซอร์เครื่องนั้นเพื่อทดสอบการกลับมาเพิ่มรายการ
- แคตตาล็อกเป็นหน้า mock ที่ไม่มีบัญชีร้านหรือการแชร์ข้อมูลจริง ข้อมูลสิทธิ์ผู้ช่วยร้านเป็นเพียงการสาธิต UI
- แคตตาล็อกลูกค้าค้นชื่อ/รหัสและกรองหมวดได้ เลือกไซซ์/สีที่มีของและกำหนดจำนวน 1–999 แพ็กบนการ์ดสินค้าก่อนบันทึก กลับมาแก้จำนวนเดิมแล้วกดบันทึกจะ **แทนค่าเดิม ไม่บวกซ้ำ** หน้ารายการที่สนใจใช้ตรวจชื่อ ตัวเลือก จำนวน และยอดประมาณ พร้อมทางกลับไปแก้หรือนำรายการออก แล้วคัดลอกข้อความไปส่งใน LINE รุ่นที่หมดทั้งรุ่นอยู่ในหัวข้อพับ สีที่หมดอยู่ใน disclosure ของไซซ์นั้น ส่วนไซซ์ที่หมดมีป้ายข้อความและเพิ่มไม่ได้
- รายการลูกค้าเป็น **คำขอรอร้านยืนยัน** ไม่กันสต็อก ไม่มีการสร้างบิลหรือแจ้งร้านอัตโนมัติ ข้อความที่คัดลอกมีรหัสอ้างอิงคงเดิมและระบุว่าเป็นฉบับล่าสุดแทนฉบับก่อนหน้า เพื่อให้ลูกค้าส่งเพิ่มข้ามวันโดยไม่ให้ร้านนับซ้ำ
- กติกาหน้าลูกค้าสำหรับทดสอบ: ขั้นต่ำประมาณ 5 โหลรวมทุกรุ่น; แพ็ก 10 ตัวนับประมาณ 1 โหล แพ็กอื่นคิดจำนวนตัวหาร 12; ถ้าต่ำกว่าเกณฑ์แสดงค่าบวกประมาณ 40 บาทต่อทุกแพ็ก ยอดนี้ยังไม่รวมค่าส่ง/ส่วนลด และร้านต้องยืนยันราคาและการนับโหลจริงอีกครั้ง
- งานถัดไปก่อนรับออร์เดอร์จริง: ฐานข้อมูลร่วมและสิทธิ์หลังร้าน, คิวคำขอพร้อมสถานะรอตอบ/รอจัด/รอชำระ/พร้อมส่ง, การแก้รายการฉบับล่าสุดโดยไม่ซ้ำ, การกันสต็อกหลังร้านยืนยัน, หลักฐานโอนเงินและข้อมูลขนส่ง; ต้นแบบนี้ยังไม่มีการซิงก์ข้ามเครื่อง
- `design/khonnai.figcraft` เป็นแบบ click-through แยกจากเว็บจริง ชื่อหน้าและเลเยอร์เป็นอังกฤษเพื่อให้ sidebar แสดงได้ แต่เนื้อหาหน้าเป็นไทย ฟอร์มในแบบไม่เก็บค่าจริง ให้ทดสอบข้อมูลและสต็อกในเว็บ
- การแกะแพ็กขาย คืน/เปลี่ยนสินค้า ส่งของบางส่วน พักบิลหลายใบพร้อมกู้หลังรีเฟรช และราคาแยก variant อยู่ระยะถัดไป

## ทดสอบกับผู้ใช้

ใช้เว็บใน `dist/user-test-site/` บนโทรศัพท์จริง ให้เจ้าของร้านและผู้ช่วยร้านลองทำงานโดยไม่บอกตำแหน่งปุ่มก่อน บันทึกผล **สำเร็จเอง / สำเร็จเมื่อช่วย / ไม่สำเร็จ**, เวลา, การกดผิด, การย้อนกลับ และคำพูดที่บ่งบอกความสับสน

1. กดแท็บ **บิล** แล้วเริ่มออกบิลทันที ค้น A-215 ไซซ์ 34 สีดำ ให้ลูกค้าดูสรุปยอดก่อนยืนยัน ถามว่าสต็อกลดหรือยังและเอกสารนี้เป็นบิลแล้วหรือยัง
2. จอง A-215 ให้ลูกค้าใหม่ เปิดสรุปยอดจากการจอง พิมพ์หรือบันทึก PDF แล้วกลับมาแก้รายการ ก่อนกดยืนยันขายจริง
3. ให้เจ้าของร้านที่ไม่คุ้นเทคโนโลยีอ่านบิลเงินสดที่ออกแล้ว ถามชื่อร้าน ชื่อลูกค้า จำนวน ราคา ยอดรวม และดูว่าคำไหนเข้าใจยาก
4. รับของหลายรุ่นจากบิลยี่ปั๊ว แก้รายการหนึ่งหลังบันทึก และให้ทำนายยอดในร้าน/จองไว้/ขายได้
5. สร้างรุ่น 3 ไซซ์ × 5 สีและรุ่นแพ็กคละสี เปรียบเทียบยอดแพ็กกับยอดตัวและตรวจความเข้าใจของจุดเตือนใกล้หมด
6. ทดสอบความเร็ว: ค้นจาก 100 รุ่น ใส่ 20 ตัวเลือกในบิลเดียว เป้าหมายไม่เกิน 10 นาที จับเวลารวมขั้นตรวจยอดก่อนยืนยัน
7. ให้รุ่นหนึ่งมี 3 ไซซ์ × 5 สี โดยบางสีหมด เปิดหน้าสต็อกและแคตตาล็อก เปรียบเทียบว่าฝั่งร้านตรวจครบและฝั่งลูกค้าเห็นเฉพาะสิ่งที่สั่งได้ แล้วลองเลิกขายสีที่มีของ/มีจองและสีที่เป็นศูนย์
8. ออกบิลจัดส่งโดยกรอกขนส่ง เบอร์ ที่อยู่หลายบรรทัด และค่าส่ง ตรวจสรุปยอดก่อนขาย บิล PDF และการแก้ค่าส่งหลังบันทึก แล้วลองสร้างการจองแบบจัดส่งก่อนเปลี่ยนเป็นบิล

หลังจบรอบถามว่า “เมนูไหนหายากที่สุด?”, “สรุปยอดกับบิลจริงแยกกันชัดไหม?”, “ถ้าใช้จริง สิ่งใดต้องแก้ก่อน?” ทดสอบบน iOS และ Android จริง โดยเฉพาะแป้นพิมพ์ การเลื่อน การพิมพ์ PDF ตัวอักษร และระยะกด ผลจากสคริปต์อัตโนมัติยังแทนการทดสอบผู้ใช้ไม่ได้

## สถานะและงานต่อ

เว็บต้นแบบมี smoke test สำหรับ flow การจอง บิล 21 รายการ ค้น 100 รุ่น รับของหลายรุ่น และตรวจจอมือถือ 12 หน้า แต่ไม่มี backend, การซิงก์หลายเครื่อง, การเก็บงานถาวร, สิทธิ์ server หรือการชำระเงินจริง ก่อนผลิตต้องพิสูจน์ความเข้าใจของผู้ใช้กับบิลกระดาษฉบับนี้ ตรวจการพิมพ์หลายหน้า และออกแบบการคืนเงิน/สินค้า, ราคาแยก variant, และการพักบิล
