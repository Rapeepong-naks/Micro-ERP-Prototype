# ปลายทางของงานหลัก

หลักที่ใช้: หลังทำรายการสำคัญให้เห็นผลลัพธ์และทางไปงานถัดไป; ปุ่มยกเลิกงานที่บันทึกแล้วต้องบอกผลต่อสต็อกก่อนยืนยัน; ปุ่ม “ไม่ยกเลิก” ต้องกลับมาที่รายละเอียดเดิมโดยไม่มีการเปลี่ยนข้อมูล. อ้างอิง [GOV.UK confirmation pages](https://design-system.service.gov.uk/patterns/confirmation-pages/) และ [NN/g confirmation dialogs](https://www.nngroup.com/articles/confirmation-dialog/).

| ต้นทาง | การกระทำ | ปลายทาง/ผลที่ควรเห็น |
| --- | --- | --- |
| ฟอร์มรับของเข้า | บันทึก | รายละเอียดรายการที่บันทึก พร้อมผลต่อสต็อก; ย้อนกลับไปหน้าแรก ไม่กลับฟอร์มที่ส่งแล้ว |
| รายละเอียดรับของเข้า | แก้ไข | ฟอร์มที่เติมข้อมูลเดิม; บันทึกแล้วกลับรายละเอียด พร้อมยอดที่ปรับตามส่วนต่าง |
| รายละเอียดรับของเข้า | ยกเลิก → ไม่ยกเลิก | ปิดกล่องยืนยัน กลับรายละเอียดเดิม ข้อมูลไม่เปลี่ยน |
| รายละเอียดรับของเข้า | ยกเลิก → ยืนยัน | แสดงสถานะยกเลิกแล้วและผลต่อสต็อก; ไม่มีปุ่มแก้หรือยกเลิกซ้ำ |
| ออกบิล | ยืนยัน | บิลที่ออกแล้ว; ย้อนกลับไปรายการบิล ไม่กลับฟอร์มออกบิล |
| สร้างการจอง | ยืนยัน | รายละเอียดการจอง; ย้อนกลับไปรายการการจอง |
| รายละเอียดการจอง | แก้ไข | ฟอร์มข้อมูลเดิม; บันทึกแล้วกลับรายละเอียดและปรับยอดจองตามส่วนต่าง |
| รายละเอียดการจอง | ยกเลิก → ยืนยัน | แสดงสถานะยกเลิก/กลับรายการ; จำนวนที่จองไว้กลับมาขายได้ |
| ปรับยอดสต็อก | บันทึก | ประวัติการเปลี่ยนแปลง; ย้อนกลับไปหน้าสต็อกของรุ่น |

ใน prototype เว็บ การแก้รับของที่ทำให้ยอดในร้านต่ำกว่าจำนวนที่จองไว้จะถูกปฏิเสธและคงฟอร์มไว้ให้แก้ จำนวนที่ขายไปหลังรับของอาจทำให้การยกเลิกรายการรับเข้านั้นทำไม่ได้เช่นกัน

FigCraft เป็น click-through ของสถานะตัวอย่าง: ปุ่มนำทางและหน้าผลลัพธ์กดได้ แต่ช่องกรอก/จำนวนในไฟล์ออกแบบไม่เก็บข้อมูลจริง การทดสอบการปรับตัวเลขและกฎสต็อกให้ใช้ prototype เว็บ
